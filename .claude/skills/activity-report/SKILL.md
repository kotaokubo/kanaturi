# activity-report — 活動報告の公開と関係者連絡

組合の放流事業と清掃活動は年1回で、報告ページの公開と関係者への連絡がセットになる。
サイト側の手順だけを踏んで連絡を落とすと、写真の使用許諾や掲載の格の調整がその年に片付かない。
ページ公開から関係者連絡までを一続きの作業として扱う。

ページ追加そのものの規約（front matter、`relative_url`、CSS のクラス命名）は
リポジトリの CLAUDE.md にある。このスキルはその手順に、公開後の連絡を接続する。

## 全体の流れ

1. 素材を受け取り、事実を確定する
2. 画像を配置する
3. ページを作る
4. 公開して反映を確認する
5. 参加した来賓と協力団体へ連絡する
6. 先方の要望に対応する

## 1. 素材を受け取り、事実を確定する

写真を受け取ったら、記事に書く事実をユーザーに確認する。推測で書かない。

- 実施日、場所（八景沖、平潟湾など）
- 魚種、稚魚の体長、放流数
- 稚魚の受け取り先（例年は神奈川県栽培漁業協会）
- 参加した来賓と協力団体、それぞれの氏名と肩書き
- 清掃活動を併せて実施したか

来賓と協力団体は後の連絡先になる。氏名の表記（先生、様）と所属を正確に控える。

## 2. 画像を配置する

`images/activities/r{年度2桁}/` に置く。命名は既存に揃える。

- 放流：`houryuuR{年度2桁}{連番2桁}.jpg` / `.webp`
- 清掃：`seisouR{年度2桁}{連番2桁}.jpg` / `.webp`

WebP は `cwebp -q 90` で生成する。写真のフォールバックは JPEG にする。
協力団体のロゴのように透過が必要なものは `images/partners/` に置き、フォールバックを PNG にする。

## 3. ページを作る

`activities/{西暦}-{魚種}.html` と、清掃を実施した年は `activities/{西暦}-seisou.html` を作る。
既存ページをコピーして front matter から書き換える。
CLAUDE.md の「ページ追加時の手順」に従い、一覧ページ、トップページ、前後ページのナビも更新する。

本文で参加者に触れるときは、次の格を守る。この区別は協力団体側から出た要望に基づく。

- 来賓：議員（衆議院議員、県議会議員）
- 協力：神奈川県栽培漁業協会、公益財団法人 山下楠太郎財団

協力団体を議員と同列に並べない。財団側から「議員の先生方と同等に紹介されるのは申し訳ない」と
明示的な要望があった経緯がある。

## 4. 公開して反映を確認する

worktree を切って作業し、PR を出してマージする。マージ後は GitHub Pages のビルドを待ち、
本番 URL（https://kanatsuri.com/）で表示を確認してから連絡に進む。
連絡メールに記事 URL を載せるので、公開前に送ると相手が 404 を見ることになる。

ローカル確認では `bundle exec jekyll serve` に PATH を通す必要がある。

```sh
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"
bundle exec jekyll serve --port 8899 --detach
```

CSS を編集したあとにブラウザで確認するときは、serve を再起動する。
`--detach` で起動したプロセスは編集を拾わないことがあり、古い `_site` を配信し続ける。
表示が変わらないときは、まず `curl http://127.0.0.1:8899/css/style.css` で
配信中の CSS を確かめる。

## 5. 参加した来賓と協力団体へ連絡する

公開したら、当日参加した関係者へメールを送る。目的は掲載の報告と、掲載内容の確認依頼である。

メールに入れる要素：

- 当日の参加への礼
- 活動報告ページに掲載した旨と記事 URL
- 記事に氏名と写真を掲載していること、不都合があれば修正する旨
- 写真データが必要なら送る旨

議員事務所には秘書宛てに届くことがある。宛名は事務所名と担当者名で書く。

連絡先は過去のスレッドに残っている。前年の送信済みメールを
`in:sent 放流` などで検索すると、宛先と文面の型が見つかる。

## 6. 先方の要望に対応する

返信で来る要望は、次の3種類が実際にあった。いずれも即応する。

**掲載の格の調整**：協力団体から「来賓ではなく協力扱いに」と要望が来る。
本文の表現を直し、直したことを返信で報告する。

**写真の使用許諾**：先方の広報で使いたい写真を指定してくる。
提供を快諾し、該当の写真を添付する。関連する構図の写真も併せて出すと、先方の選択肢が増える。
Gmail コネクタ経由での添付は画像を base64 で渡すことになり現実的でないため、
下書きだけ作ってユーザーに添付してもらう。

**バナーの掲載**：先方サイトへのリンクとバナー画像を提供され、掲載を打診される。
記事末尾の `.partners` セクションに載せる。バナーは記事写真より小さくする。
デスクトップ 200px、モバイル 150px で、写真（それぞれ約 259px、166px）より小さい。

要望が遠慮の形で来ることがある。「申し訳ないかなと思いました（笑）」のような書き方は、
実質的な依頼として読む。表面的に「問題ない」と書かれていても、
気にしている点が名指しされていれば直す。

対応したら、何をどう直したかを返信で具体的に伝える。
